# Release gate

Before **any** release tag, build both artifacts from the same revision using `release.ps1 -Tag v<version> -NoPublish` and `release.ps1 -Tag v<version> -NoPublish -Qa`. The production artifact is `dist-release/HeyListen-Get.zip`; the QA artifact is `dist-release/HeyListen-Get-qa.zip` and must never be published.

Run `qa/simulate-friend.ps1 -Zip dist-release/HeyListen-Get-qa.zip` for fixture flows and `python qa/check_production_trust.py --zip dist-release/HeyListen-Get.zip` to assert the actual release executable ignores all three trust-sensitive seam variables. Both checks must pass. Obtain an independent review of the diff since the last tag from a different agent/session and record sign-off in the PR, commit message, or `qa/reviews/`. Do not tag until the entire gate passes.

The GUI simulation sets `SDL_VIDEODRIVER=dummy` and `SDL_RENDER_DRIVER=software`, and requires the fixture install to reach the GUI's READY state. Safety checks sample descendant PID/creation-time identities while each flow runs and reject recycled PIDs; short-lived reparented processes can still escape sampling, so this is not exhaustive crash safety. The 2026-11-17 merged-gate prior-update run timed out after staging; a subsequent run swapped in about one second. The original 90-second outlier predates phase instrumentation and its root cause remains unknown. Ten loaded trials with the helper-startup marker did not reproduce it; `qa/update-stress-results.json` records phase durations and total time. The prior-update gate retains 33 s (three times the earlier measured 10.961 s worst, rounded up); the latest worst was 8.547 s. Treat the unexplained outlier as owner-accepted residual risk with the timed phases and bounded gate as safety net; this is not independent reviewer sign-off.

The ZIP-root GUI case downloads multiple loopback bundles and pauses assembly before the fixture is complete. It checks the launcher trace of the displayed percentage: starts at 0, advances without disappearing or decreasing, stays below 100 until success, then shows 100/READY. It also checks bundle verification and installed file hashes. This is a QA ZIP fixture, not a clean-profile GUI install of the public ZIP against the live channel.

For the prior-release check, pass `-OldZip` with a separately built QA-enabled `0.0.1` zip: set `APP_VERSION`, the standalone launcher fallback version, and `sources.json` in an isolated copy, then build with `-Tag v0.0.1 -NoPublish -Qa`.

`SILVER_LANTERN_PAUSE_AT`, `SILVER_LANTERN_PAUSE_READY` and `SILVER_LANTERN_PAUSE_RELEASE` provide deterministic QA checkpoint synchronization: the ready file contains the paused PID, and release must appear within 30 seconds. Production ignores all three. `SILVER_LANTERN_GAME_MANIFEST`, `SILVER_LANTERN_TEST_ASSET_URL` and `SILVER_LANTERN_ALLOW_LOCAL_UPDATE` work only in QA builds or source runs. `SILVER_LANTERN_TEST_GUI_INSTALL=1` also requires dummy SDL and a fixture manifest. Production builds bake `QA_SEAMS=False`; inherited environment variables cannot enable these trust overrides. Source runs default to QA seams when no generated flag module is present.
