# Independent review: v1.7.0

**Verdict: FIX-FIRST**  
Reviewed `v1.6.9..main` in an independent clone, 2026-11-17.

## Findings

1. **High — staging symlink bypasses running-executable protection and path confinement** — `Get-HeyListen.py:2014-2018,2103-2108` (also `2398-2404`). The check resolves the final manifest target, not its `<target>.heylisten-new` staging path. If that staging path already is a symlink to the running executable (or any writable file outside the game directory), `open(..., 'wb')` follows it and truncates/writes the referent before the final replace. The final target can be completely unrelated to the protected executable, so case normalization and resolving the target do not prevent this. Windows may deny writing an executable image in use, but that is an OS sharing constraint, not the promised protection; other writable outside files are directly exposed. Reject reparse points/symlinks for staging and checkpoint files and open them without following links, preferably via verified directory handles; test both formats with a staging symlink to an outside sentinel and to the running executable. Also revalidate at use, not just planning time.

2. **Medium — retry label can hide an unrelated real exception** — `Get-HeyListen.py:713-717`; `qa/simulate_friend.py:81-86`. `traceback.format_exc()` includes exception chains. If an operation raises `PermissionError` while handling another exception, every line of both tracebacks is tagged `recoverable-retry:`. If a later attempt succeeds, the QA crash detector ignores the earlier real underlying exception completely. Even terminal lock failures are initially labeled recoverable before the cap/deadline decision. Log only the specific retryable exception without its chained traceback, logging unexpected chained causes unlabelled, and label only when an actual retry will occur; add a chained-exception regression test.

3. **Medium — launcher executable leaks into game bundle** — `pack-game.py:68-70`; `launcher.py:474`. Root `HeyListen-Get.exe` is a supported launcher-owned executable but does not match the exclusion prefixes. Packing a live folder containing it silently includes it as game content, allowing an outdated launcher to be installed by the game channel. Exclude exact owned launcher artifacts, including this name, and test root and supported launcher locations without excluding actual game executables. Conversely, the current broad `Ocarina of Time*`, `Run Silver Lantern*`, and `SilverLantern*` prefix patterns can exclude legitimate unrelated root executables; prefer precise known artifact names or a documented explicit allowlist.

## Scope and verification

Reviewed self-executable matching, path-escape diagnostics, retry classification and caps, Restart Manager ctypes lifecycle, orphan-worker handling, pack exclusions, and QA pause build gating. `game_path` identifies the offending entry; resolved target comparisons handle ordinary case and symlink aliases, and a non-running executable is not categorically skipped. Running-process collection is a snapshot, not an atomic guarantee. Restart Manager closes started sessions in `finally`; no ctypes defect established. Production pause calls pass `build_flags.QA_SEAMS`; packaged production trust was not independently exercised. The source fallback intentionally enables QA seams when build flags are absent, so production packaging must continue to require the generated false flag. No new single-instance mechanism was established by this review.
